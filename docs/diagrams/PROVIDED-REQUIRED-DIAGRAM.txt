## Legend

**○ (Lollipop)** = PROVIDED Interface  
- Component offers this service to others
- Other components can depend on this interface

**◐ (Socket)** = REQUIRED Interface  
- Component needs this service from another component
- Must be connected to a component that provides this interface

**Connections:**
- Solid arrows (→) = dependency/usage
- Dotted lines = interface contract

---

## How to Draw This in PowerPoint/Draw.io

### For Each Component:
1. Draw a **rectangle** for the component
2. Add **small circles (○)** on the edge for PROVIDED interfaces
3. Add **small semicircles (◐)** on the edge for REQUIRED interfaces
4. Label each interface
5. Draw **lines** connecting provided to required interfaces

### Example for StockDataManager:

```
Top of box: ○ IStockDataManager (provided - sticks out)

Bottom of box: 
◐ IRepository (required - socket in)
◐ IAPIService (required - socket in)
◐ ICacheManager (required - socket in)
```

### Color Scheme:
- Presentation Layer: Light Blue
- Business Logic Layer: Light Yellow
- Data Access Layer: Light Purple
- Provided interfaces: Green circles
- Required interfaces: Red semicircles

## Key Architecture Principles Shown

1. **Interface-Based Design**: Components interact through interfaces only
2. **Dependency Inversion**: High-level components depend on abstractions (interfaces), not concrete implementations
3. **Separation of Concerns**: Each component has specific provided services
4. **Loose Coupling**: Components can be swapped as long as they provide/require the same interfaces
5. **Clear Contracts**: Provided and required interfaces define explicit contracts

---

*This is component-based architecture with explicit interface contracts - NOT inheritance!*

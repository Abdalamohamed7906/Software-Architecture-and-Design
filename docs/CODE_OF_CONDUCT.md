# Team Code of Conduct
## Share Price Comparison Application Project

---

## 1. Purpose

This Code of Conduct establishes the behavioral expectations and working agreements for our team. All team members agree to uphold these standards to ensure a productive, respectful, and collaborative environment throughout the project.

**Version**: 1.0  
**Effective Date**: February 6, 2026  
**Review Date**: Sprint 2 Planning

---

## 2. Core Values

### 2.1 Respect
- Treat all team members with dignity and respect
- Value diverse perspectives and experiences
- Listen actively when others are speaking
- Avoid interrupting or dismissing others' contributions
- Disagree professionally and constructively

### 2.2 Collaboration
- Share knowledge and help team members grow
- Ask for help when needed without hesitation
- Provide support to struggling team members
- Celebrate team successes together
- Take collective ownership of problems and solutions

### 2.3 Accountability
- Complete assigned tasks on time
- Communicate early if deadlines cannot be met
- Take responsibility for mistakes
- Follow through on commitments
- Contribute equitably to the project

### 2.4 Quality
- Write clean, well-documented code
- Follow established coding standards
- Test code before committing
- Conduct thorough code reviews
- Prioritize long-term maintainability

### 2.5 Transparency
- Communicate progress regularly
- Share blockers and challenges openly
- Document decisions and rationale
- Keep project management tools updated
- Be honest about capabilities and capacity

---

## 3. Communication Standards

### 3.1 Meetings
- **Attendance**: All team members must attend scheduled meetings unless excused in advance
- **Punctuality**: Arrive on time and prepared
- **Participation**: Actively contribute to discussions
- **Focus**: Minimize distractions (phones, laptops for notes only)
- **Minutes**: Designate a note-taker for each meeting

### 3.2 Online Communication
- **Response Time**: Respond to messages within 24 hours
- **Channels**: Use agreed-upon platforms (e.g., Slack, Teams, Discord)
- **Clarity**: Write clear, concise messages
- **Tone**: Maintain professional and friendly tone
- **Availability**: Update status when unavailable

### 3.3 Code Reviews
- **Timeliness**: Review pull requests within 48 hours
- **Constructiveness**: Provide helpful, specific feedback
- **Respect**: Critique code, not people
- **Learning**: Explain reasoning behind suggestions
- **Appreciation**: Acknowledge good work

---

## 4. Workflow Standards

### 4.1 Version Control (Git/GitHub)
- **Branching**: Create feature branches from `develop` (never commit directly to `main` or `develop`)
- **Branch Naming**: Use descriptive names (e.g., `feature/data-persistence`, `bugfix/date-validation`)
- **Commits**: Write clear, descriptive commit messages following conventional commits format
- **Pull Requests**: 
  - Include description of changes
  - Link to related issues
  - Request reviews from at least 2 team members
  - Address review comments promptly
- **Merging**: Only merge after approval and passing tests

### 4.2 Coding Standards
- **Language**: Java 11+ following Oracle Java conventions
- **Documentation**: 
  - JavaDoc for all public methods and classes
  - Inline comments for complex logic
  - README for each module
- **Formatting**: Use consistent IDE formatting settings
- **Testing**: Write unit tests for new functionality
- **Naming**: Use descriptive, meaningful names for variables, methods, classes

### 4.3 Project Management
- **Tool**: [Specify: Jira/Trello/GitHub Projects/Azure DevOps]
- **Task Updates**: Update task status daily
- **Time Tracking**: Log time spent on tasks
- **Blockers**: Flag blockers immediately
- **Sprint Planning**: Participate actively in planning sessions

---

## 5. Conflict Resolution

### 5.1 Process
1. **Direct Communication**: Attempt to resolve conflicts directly with the involved party
2. **Mediation**: If unresolved, involve a neutral team member
3. **Team Discussion**: Bring to team meeting if needed
4. **Escalation**: Contact module instructor as last resort

### 5.2 Technical Disagreements
- Present evidence and rationale for your position
- Listen to alternative viewpoints with an open mind
- Use data and best practices to guide decisions
- Accept team decisions even if you disagree
- Document the decision and reasoning

---

## 6. Work Distribution

### 6.1 Principles
- **Equity**: Work divided fairly based on skills and availability
- **Balance**: Consider academic and personal commitments
- **Transparency**: Task allocation visible to all team members
- **Flexibility**: Reassign tasks if circumstances change
- **Communication**: Discuss workload concerns openly

### 6.2 Sprint Planning
- Team collectively estimates task effort
- Members volunteer for tasks based on interest and expertise
- Unassigned tasks allocated by consensus or rotation
- Adjust allocation if someone is overloaded

## 8. Academic Integrity

### 8.1 Commitments
- All work submitted is our own
- Properly attribute external code, libraries, and resources
- Do not share code with other teams
- Do not plagiarize code from online sources
- Cite all references in documentation

### 8.2 Collaboration
- Collaboration within the team is encouraged
- Discussing approaches with other teams is acceptable
- Sharing actual code with other teams is prohibited
- Using AI assistants (e.g., GitHub Copilot) is permitted but must be acknowledged

---

## 9. Contribution Tracking

### 9.1 Git Commit Standards
- Commit frequently with meaningful messages
- Each member should have regular commits
- Pair programming commits should credit both authors

### 9.2 Individual Reflection
- Each member maintains notes on their contributions
- Document challenges and learnings
- Prepare evidence for individual reflection report

---

## 10. Penalties for Violations

### 10.1 Minor Violations (late to meetings, missed standup)
- **First Occurrence**: Verbal reminder
- **Repeat Occurrences**: Team discussion to address issue

### 10.2 Major Violations (missed deadline, no communication, dishonesty)
- Team meeting to discuss impact
- Development of improvement plan
- Potential task reassignment
- If unresolved, inform instructor

### 10.3 Severe Violations (plagiarism, academic dishonesty)
- Immediate reporting to module instructor
- Follow university academic integrity procedures
